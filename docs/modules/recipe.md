# The recipe module

`recipe` is toon-recipe merged into the household app: recipes with search and filters, tags and
collections, URL / photo / PDF import, the meal plan with its cook log, shopping lists (the one feature
that is editable offline), saved loyalty cards, uploads with thumbnails and the print stylesheet. It is
enabled by default on every new household (`DEFAULT_ENABLED_MODULES` in
`packages/shared/src/modules/registry.ts`). This document is the module's reference: what it owns (section
1), toon-recipe's locked decisions with their status here (section 2), the household app's own decisions
for it (section 3), every gotcha (section 4) and how to verify a change (section 5). The contract every
module obeys is `docs/SPEC.md` section 2; the core-wide rules are in `CLAUDE.md`; the HTTP contract of
this module is `docs/API.md`, section "Recipe module".

Read this file before touching `apps/api/src/modules/recipe/`, `apps/web/src/modules/recipe/` or
`packages/shared/src/modules/recipe/`. toon-recipe's own `CLAUDE.md` stays binding inside the module
(SPEC D13); section 4b maps its 83 gotchas to where each one lives now. The language of the document is
English (D15); German UI strings are quoted byte-identical.

## 1. What the module owns

### 1.1 Tables

Seventeen SQL tables, every one prefixed `recipe_`, in `apps/api/src/modules/recipe/schema.ts`
(aggregated as `recipeTables` and re-exported flat by `apps/api/src/db/schema.ts`). The migration is
`apps/api/drizzle/0001_recipe.sql`, generated by drizzle-kit. The drizzle identifiers are toon-recipe's
and carry no prefix (section 3, decision H2). `group_id` of the source is `household_id`.

| SQL table | drizzle identifier | Holds |
| --- | --- | --- |
| `recipe_recipes` | `recipes` | the recipe; `title_fold` and `description_fold`, the stored `last_cooked_at` |
| `recipe_recipe_ingredients` | `recipeIngredients` | ingredient lines; `name_fold` |
| `recipe_recipe_steps` | `recipeSteps` | method steps |
| `recipe_tags` | `tags` | tags with `kind` (`course` or `free`, default `free`) |
| `recipe_recipe_tags` | `recipeTags` | recipe to tag join |
| `recipe_collections` | `collections` | collections with an optional cover image |
| `recipe_collection_recipes` | `collectionRecipes` | collection to recipe join |
| `recipe_meal_plan_entries` | `mealPlanEntries` | the meal plan; `planned_on` is text `YYYY-MM-DD` |
| `recipe_recipe_cook_log` | `recipeCookLog` | one row per "Gekocht" |
| `recipe_import_drafts` | `importDrafts` | editable import drafts (nothing reaches `recipe_recipes` before commit) |
| `recipe_shopping_lists` | `shoppingLists` | named lists; `bought_cleared_at` watermark |
| `recipe_shopping_list_items` | `shoppingListItems` | list lines, unique on `(list_id, merge_key)`, no `checked` column |
| `recipe_shopping_list_catalog` | `shoppingListCatalog` | the "Häufig gekauft" feed; `hidden_at`, `use_count` |
| `recipe_shopping_bought_items` | `shoppingBoughtItems` | the bought-item log (90-day TTL) |
| `recipe_shopping_list_recipes` | `shoppingListRecipes` | list to recipe join |
| `recipe_shopping_mutations` | `shoppingMutations` | applied `mutationId`s (exactly-once for replayed offline writes) |
| `recipe_cards` | `cards` | saved loyalty cards, hung off `users`, not off a household |

Index names are `recipe_<table>_household_…` because SQLite index names are global. The one drizzle
relation set is the recipe tables' own; the core tables gain no recipe side.

### 1.2 API routers and hooks

The manifest is `apps/api/src/modules/recipe/index.ts` (`recipeModule`, listed in
`apps/api/src/modules/index.ts`). Its two routers are composed in `apps/api/src/modules/recipe/routes/index.ts`:

| Router | Mount point | Files | Middleware |
| --- | --- | --- | --- |
| `householdRouter` (`recipeHouseholdRouter`) | `/api/households/:householdId/recipe/…` | `routes/imports.ts` at `/imports`, `routes/shopping.ts` at `/shopping-lists`, `routes/plan.ts` at `/plan`, then `routes/recipes.ts` at `/` (recipes, tags, collections, cook log) | `requireSession()`, `requireHouseholdRole("member")`, `requireModule("recipe")` from `apps/api/src/modules/mount.ts`; each file adds `requireVerifiedEmail()` itself (`use("*")`, non-GET only); `requireHouseholdRole("admin")` per route where needed (tag delete) |
| `userRouter` (`recipeUserRouter`) | `/api/recipe/cards/…` | `routes/cards.ts` | `requireSession()` and `requireVerifiedEmail()` in the file; NOT behind `requireModule`: a card follows its owner (decision RD11) |

Order is load-bearing: imports, shopping and plan are registered BEFORE the catch-all recipe router
(toon-recipe's mount order, SPEC D8). Hono copies a sub-app's routes when `.route()` is called, so every
router file registers its handlers at module top level. The services mirror toon-recipe's `services/`
one to one under `apps/api/src/modules/recipe/services/{recipes,import,ocr,plan,shopping,cards}/`
(`import/` has `url/`, `html/`, `ocr/`). The routes and their request and response shapes are documented
row by row in `docs/API.md`, checked by `apps/api/test/api-doc.test.ts`.

Manifest hooks implemented (the `ApiModule` contract, `apps/api/src/modules/types.ts`):

| Hook | What the recipe module does |
| --- | --- |
| `healthFeatures` | `{ ocrImport, pdfImport }` from `isOcrImportEnabled()` / `isPdfImportEnabled()` (`services/import/capabilities.ts`), merged into `/api/health` `features` |
| `afterMigrate` | `backfillFoldedColumns` (`apps/api/src/modules/recipe/migrate.ts`): idempotent, no transaction (gotcha "Fold columns and the backfill") |
| `shutdown` | `shutdownOcr` (`services/ocr/index.ts`), called from the SIGTERM/SIGINT handler of `apps/api/src/index.ts` |
| `seedDemo` | `seedRecipeDemo` (`apps/api/src/modules/recipe/seed.ts`): tags, three German recipes, a plan week, a cook log, the shopping list "Rewe" with bought history; content language is German on purpose |
| `uploadReferences` | every stored upload a recipe row holds: `recipe_recipes.image_url`, `recipe_collections.cover_image_url`, `recipe_import_drafts.source_meta` (`storedPath`) and `recipe_import_drafts.parsed` (`imageUrl`); a missing column makes `uploads:gc` delete a live image |

The module has no `onHouseholdCreated`, `onEnable`, `onMemberRemoving` or `start`: a recipe row names
the household, never a person (cards belong to the user and cascade with the user).

### 1.3 Shared package

`packages/shared/src/modules/recipe/` (barrel `index.ts`, re-exported by `packages/shared/src/index.ts`,
the only entry): the pure content parsers and maths `units.ts`, `ingredients.ts`, `numbers.ts`,
`duration.ts`, `tags.ts`, `shopping.ts`, the hand-rolled encoders `barcode.ts` and `qr.ts`, and the Zod
schemas `schemas/{recipe,plan,import,shopping,card}.ts`. `foldText` and the calendar helpers are core
(`packages/shared/src/core/text.ts`, `packages/shared/src/core/calendar.ts`). Tests are flat in
`packages/shared/test/` under toon-recipe's file names.

### 1.4 Scripts and environment

- `bun run seed` runs `seedDemo` (above). `bun run uploads:gc` (`apps/api/scripts/uploads-gc.ts`)
  consults `uploadReferences`. `bun run db:migrate` runs `afterMigrate`. `bun run migrate:legacy`
  (`apps/api/scripts/legacy/recipe.ts`) imports toon-recipe's rows and relies on the backfill for the
  folded columns. `bun run recipe:localize-images [-- --dry-run]` (`apps/api/scripts/localize-images.ts`)
  copies every hero image and collection cover that is still a remote URL into `UPLOAD_DIR` (the one-off
  catch-up for rows written before the write paths localized them; an unreachable one stays remote).
- Environment switches read by the module (`apps/api/src/env.ts`), all off or conservative by default:
  `IMPORT_OCR_ENABLED` (photo import, needs the `tesseract` binary), `IMPORT_PDF_ENABLED` (PDF import,
  needs `pdftoppm`; unset follows the photo flag, an explicit `0` splits them), `IMPORT_OCR_CONCURRENCY`
  (default 1), `TESSERACT_LANGS` (`deu+eng`), `TESSERACT_BIN`, `PDFTOPPM_BIN`,
  `IMPORT_ALLOW_PRIVATE_HOSTS=1` (dev only, ignored in production: lets the URL importer fetch a
  localhost fixture, otherwise the SSRF guard blocks it) and `UPLOAD_DIR` (core, default
  `./data/uploads`). The image carries the OCR binaries only for `--build-arg WITH_OCR=1` /
  `WITH_PDF=1` (`Dockerfile`; `.github/workflows/release.yml` publishes `WITH_OCR=1 WITH_PDF=0`).

### 1.5 Web

The manifest is `apps/web/src/modules/recipe/index.ts` (`recipeModule`, literal-typed with only
`satisfies WebModule<"recipe">`, listed in `apps/web/src/modules/index.ts`). Its layout route is
`recipeLayoutRoute` in `apps/web/src/modules/recipe/routes.tsx` (`getParentRoute: () => householdScopedRoute`,
`component: moduleLayoutComponent("recipe")`), every screen a `lazyRouteComponent`.

URL scheme (decision H1), all below `/recipe`:

| URL | Screen |
| --- | --- |
| `/recipe` | library (`RecipeListPage`), search params `RECIPE_FILTER_PARAMS` |
| `/recipe/search` | redirect to `/recipe`, declares the same params |
| `/recipe/recipes/new`, `/recipe/recipes/$recipeId`, `/recipe/recipes/$recipeId/edit` | create, detail, edit |
| `/recipe/import`, `/recipe/import/$draftId` | import, draft review |
| `/recipe/collections`, `/recipe/collections/$collectionId`, `/recipe/tags` | organise |
| `/recipe/shopping`, `/recipe/shopping/$listId`, `/recipe/shopping/history`, `/recipe/shopping/cards` | lists, one list, bought history (`SHOPPING_HISTORY_PARAMS`), the card wallet |
| `/recipe/plan` | meal planner, search param `week` (`PLAN_SEARCH_PARAMS`, normalised to its Monday) |

The three `*_PARAMS` arrays live in `routes.tsx` (toon-recipe kept them in its `router.tsx`):
`RECIPE_FILTER_PARAMS` is `q`, `tags`, `collectionId`, `maxMinutes`, `difficulty`, `sort`;
`PLAN_SEARCH_PARAMS` is `week`; `SHOPPING_HISTORY_PARAMS` is `listId`, `offset`. `pick()` drops anything
unlisted, so a new filter needs a line in its array.

Navigation (`docs/SPEC.md` D6): the phone tab bar shows Rezepte `/recipe` (exact), Plan `/recipe/plan` and
Einkauf `/recipe/shopping`, and the shell appends Profil `/settings`. Sidebar-only are Sammlungen
`/recipe/collections` and Tags `/recipe/tags`, in that order, and the shell appends Gruppen. Labels are
catalog keys (`common.nav.*`), never strings. The reachability rule of toon-recipe's "Navigation" section
carries over, and these links are the enforcement, not a description:

- Sammlungen and Tags are reached through the "Sammlungen verwalten" / "Tags verwalten" links in
  `RecipeFilterRail` (from `lg`) and `RecipeFilterSheet` (below it), both in
  `apps/web/src/modules/recipe/features/recipes/components/`. There is no other phone route to either.
- Karten (`/recipe/shopping/cards`) is reached from the `CardsCard` panel on `/recipe/shopping`
  (`apps/web/src/modules/recipe/features/cards/components/CardsCard.tsx`); it is not a tab and not a
  secondary item.
- Importieren and Neues Rezept are reached from the `+` of the library header, which opens
  `LibraryCreateMenu` (`ActionMenu`), the only phone route to either. It is hidden, not disabled, while
  `useEmailVerificationBlock()` is set. The PWA manifest shortcuts (`apps/web/pwa-manifest.ts`) point at
  `/recipe/import` and `/recipe/recipes/new`.
- Gruppen is core (`/households`, reached from the households card on `/settings`).
- Search is not a destination: add a field to `RecipeFilterFields` (rendered by both filter surfaces)
  instead of a search screen.

Other web pieces: `HomeCard.tsx` (the Home card: a seven-day strip from
`features/plan/components/HomeWeekStrip.tsx` and the pure `features/plan/lib/home-week.ts`, plus the
active shopping list's open count), `nav-trailing.tsx` (`NavItem.trailing`: the sidebar's recipe count, the
Plan "Neu" pill and the shopping count), `lib/{api,queries,format}.ts` (shims: `export * from "@/lib/<x>"`
plus the module's own fetchers, keys and formatters) and `features/{recipes,collections,tags,import,
shopping,cards,plan}/` mirroring toon-recipe's `features/`. Nothing lives under `apps/web/src/features/`.

Catalog namespaces: six files in `apps/web/src/modules/recipe/catalogs/` (`recipes`, `organise`, `plan`,
`shopping`, `import`, `cards`, each `.de.ts` and `.en.ts`) merged by `catalogs/index.ts` into the
literal-typed `recipeDe` / `recipeEn`. Key prefixes: `recipe.recipes.*`, `recipe.shopping.*`,
`recipe.plan.*`, `recipe.import.*`, `recipe.cards.*`, and from toon-recipe's `groups.*` the recipe-owned
`recipe.collections.*`, `recipe.collectionDetail.*`, `recipe.tags.*`, `recipe.tagCombobox.*` and
`recipe.count.recipes`. Values are byte-identical to toon-recipe's; toon-recipe's `ui.*` is core
`common.*`.

Query keys: household data `["toon","household",<id>,"recipe",<segment>,…]` with toon-recipe's segment names
(`recipes`, `recipe`, `tags`, `collections`, `collection`, `imports`, `import`, `shopping-lists`,
`shopping-list`, `plan`, `plan-shopping`, `shopping-bought`, `shopping-catalog`); user data
`["toon","recipe","cards"]`; the import draft `["toon","recipe","import-draft",<id>]`; shopping mutations
`["toon","recipe","shopping",<op>]`.

Persist allow-list (`persistQueryAllowList` in the manifest; the shell assembles the policy, SPEC D9):
household segments `recipes`, `recipe`, `tags`, `collections`, `collection`, `shopping-lists`,
`shopping-list`, `plan`, `shopping-bought`, and the user key `["recipe","cards"]` exactly (the wallet only,
nothing below it). Deliberately absent: `imports`, `import`, `import-draft` (mid-edit state comes from the
server), `plan-shopping` (a live server diff, stale offline is worse than absent) and `shopping-catalog`.
The offline outbox is `persistMutationNamespaces: [["recipe","shopping"]]` with
`mutationDefaults: registerShoppingMutationDefaults` (`features/shopping/lib/offline.ts`).

Service-worker rules (`apps/web/vite.config.ts`, first match wins): `NetworkOnly` for
`/api/households/<id>/recipe/imports`, `…/recipe/shopping-lists`, `…/recipe/plan` and `/api/recipe/cards`
(each one's offline copy IS the persisted TanStack cache), all before the one recipe `NetworkFirst` rule
for `…/recipe/(recipes|tags|collections)` (cache `toon-api-recipes`, 4 s timeout); `/uploads/` is
`CacheFirst`. `/api/auth/` is `NetworkOnly` first of all; finance adds one `NetworkOnly` rule of its own.
`/api` and `/uploads` stay out of the navigation fallback, and `/plan` is a navigation path as well as an
API prefix so it never goes in the denylist.

## 3. Household decisions for the module

Taken by `docs/plans/m2-recipe-module.md` section 1 (and later milestones) and recorded here as the
module's own. SPEC section 1 stays the authority; none of these deviates from it except where an ADR is
named.

- **H1. URL scheme.** Every toon-recipe path gained the `/recipe` prefix (section 1.5). `/search` stays a
  redirect with the same params. toon-recipe's old paths reach the new app through the Caddy redirects of
  ADR 0008 (`docker/Caddyfile`), not through this module.
- **H2. Unprefixed TS identifiers.** SQL tables and indexes are `recipe_`-prefixed, the drizzle identifiers
  keep toon-recipe's names (`recipes`, `tags`, `cards`, …) so the services port with path changes only.
  The price is paid by the other module: finance's identifiers carry a `finance` prefix because
  `apps/api/src/db/schema.ts` re-exports flat and recipe owns `tags`.
- **H3. Fold columns are NOT NULL without a default.** `title_fold`, `description_fold` and `name_fold`
  have no `DEFAULT ''` in the fresh `0001_recipe.sql` (toon-recipe's default existed only to ALTER a
  populated table). The backfill moved verbatim to `apps/api/src/modules/recipe/migrate.ts` and runs as
  `afterMigrate`.
- **H4. Import query keys are rooted at `"toon"`.** toon-recipe's `["import", …]` keys became
  `["toon","household",<id>,"recipe","import",…]` and `["toon","recipe","import-draft",<id>]`.
- **H5. Cards stay user-scoped.** `/api/recipe/cards` is a `userRouter`; the household's module switch does
  not hide a user's wallet (`apps/api/test/middleware.test.ts` shows `/api/recipe/cards` answering a session alone, with
  no household and no module row involved).
- **H6. The recipe count is the module's own query (ADR 0001).** The core cannot count a module's rows, so
  `household.detail.meta` and `household.danger.warning` lost their recipe count and
  `household.count.recipes` was not ported (`docs/adr/0001-household-copy-without-recipe-counts.md`). The
  module supplies its own number (gotcha "The library's recipe count is the module's own query") and keeps
  `recipe.count.recipes` in its catalog with toon-recipe's value.
- **H7. The module routers do not apply the session and role middleware.** `mountModules` runs
  `requireSession()`, `requireHouseholdRole("member")` and `requireModule("recipe")` first; the ported
  routers deleted their own copies and keep `requireVerifiedEmail()`. toon-recipe's
  `services/import/middleware-bridge.ts` is not ported (import route tests use real sessions).
- **H8. Cross-household guard (SPEC D8).** The household comes from `:householdId` only; every by-id
  lookup filters by it and answers `404 not_found` for another household's id (cards: another user's
  card). `apps/api/test/recipe-cross-household.test.ts` addresses every by-id route and compares its probes
  with the routers' declared `:param` routes, so a new by-id route fails the test until it is added.
- **H9. The manifest's static import graph stays shell-free.** `index.ts`, `routes.tsx`, `HomeCard.tsx`,
  `nav-trailing.tsx`, the catalogs and `features/shopping/lib/offline.ts` import neither `@/modules` nor
  `@/components/layout`; screens are lazy. `manifest.test.ts` and `persist.test.ts` import the manifest
  first, which proves it (SPEC section 2).
- **H10. Design pass (M4).** Every recipe screen renders `PhoneHeaderRow` itself except the recipe detail,
  whose hero owns the top edge (`apps/web/src/modules/recipe/phone-header.test.ts` reads `routes.tsx` for
  the screen list). `apps/web/src/styles/design-system.test.ts` is the Table D gate and pins toon-recipe's
  34 inherited arbitrary `text-[…]` sizes, its four uppercase labels and its two `←` back links as
  recorded exceptions; converting them is an owner decision, not a cleanup.
- **H11. The phone detail's print action row (M7).** The servings scaler and "Zur Einkaufsliste" of the
  phone ingredients panel carry `data-print="hide"` like the desktop branch
  (`apps/web/src/modules/recipe/features/recipes/RecipeDetailPage.tsx`, guarded by `print-css.test.ts`);
  `print.css` is unchanged.

## 4. Gotchas

### 4a. Gotchas moved here from CLAUDE.md

These eight were in the household `CLAUDE.md` "Gotchas in use" and belong to this module; `CLAUDE.md` keeps
a one-line pointer. Paths are repo-relative.

- **Recipe tables and indexes are prefixed, their TS identifiers are not.** SQL names are `recipe_*`
  (index names `recipe_…_household_…`, because SQLite index names are global), but the drizzle
  identifiers stay toon-recipe's (`recipes`, `tags`, `recipeTags`, `cards`, `shoppingLists`, …) so the
  services port with path changes only; the column property is `householdId`. `apps/api/src/db/schema.ts`
  re-exports every module's schema FLAT, which is why finance's identifiers DO carry a `finance` prefix
  (`docs/modules/finance.md`). Raw SQL strings and `explain` text follow the SQL names.

- **Fold columns and the backfill.** `title_fold`, `description_fold`, `name_fold` are `NOT NULL`
  with no default (the fresh `apps/api/drizzle/0001_recipe.sql` has no `DEFAULT ''`; services write them
  through `foldText`). `backfillFoldedColumns` lives in `apps/api/src/modules/recipe/migrate.ts` and runs
  as the module's `afterMigrate` after every `runMigrations` (db:migrate, seed, tests): idempotent, no
  transaction. `migrate:legacy` (`apps/api/scripts/legacy/recipe.ts`) relies on it for imported rows.

- **Import route tests use real sessions.** toon-recipe's `services/import/middleware-bridge.ts` is not
  ported: it only stubbed the session and group middleware, and the mount chain now runs the real
  ones. `apps/api/test/import/routes.test.ts` and `apps/api/test/import/ocr-disabled.test.ts` log in
  through the shared DB plus the file-backed import DB (`setImportDbForTests`, in
  `apps/api/src/modules/recipe/services/import/db.ts`). OCR and PDF flags, `setMailer`,
  `setVerifiedEmailRequired`, `setOcrEngine`, `setPdfRasterizer` are handed back in `afterAll`; never
  `mock.module`. `apps/api/test/import/pdf-rasterize.test.ts` needs poppler's `pdftoppm` and fails, not
  skips, without it.

- **Import query keys are rooted at `"toon"` (decision 14).** `["toon","household",id,"recipe","import",
  "drafts"|"tags",…]` for household lists and `["toon","recipe","import-draft",draftId]` for the
  user-scoped draft (a draft resolves across the user's households). Commit and delete invalidate both
  roots; none of these segments is in the persist allow-list, so no import data is persisted.
  `useCommitDraft` calls `invalidateAfterRecipeMutation` (`apps/web/src/modules/recipe/lib/queries.ts`;
  every module key now contains `"recipe"`, so toon-recipe's "contains recipe" predicate would match
  everything). The keys are `importKeys` in `apps/web/src/modules/recipe/features/import/lib/queries.ts`.

- **The library's recipe count is the module's own query (ADR 0001, decision 13).**
  `useHouseholdRecipeCount(householdId)` (`apps/web/src/modules/recipe/features/recipes/lib/queries.ts`) is
  an UNFILTERED `recipesQuery(householdId, { limit: 1 })` whose `total` is the count; its key sits under
  `recipesRoot`, so every recipe mutation refreshes it, and it is persisted like every `recipes` key.
  `RecipeListPage` feeds it into `recipe.recipes.list.groupSummary` ("Familie · N Rezepte" on a
  phone) and `sharedSummary` ("Geteilt mit Familie · 1 Mitglied · N Rezepte" at `lg`) and renders the
  subtitle only once the count is known. Never use the filtered list's `total` there (wrong whenever a
  filter is set; the headless run checks the subtitle stays at N under `?q=`).

- **The shopping list outbox is wired through the manifest.** `registerShoppingMutationDefaults`
  (`apps/web/src/modules/recipe/features/shopping/lib/offline.ts`) is the manifest's `mutationDefaults`
  (no module-scope call any more), `persistMutationNamespaces: [["recipe","shopping"]]` persists only
  paused `["toon","recipe","shopping",…]` mutations, and every queued write carries a client-minted
  `mutationId` (the API applies one `mutationId` once, so a replayed request cannot turn 500 g into
  1 kg). toon-recipe's gotcha "THE SHOPPING LIST IS THE ONE THING EDITABLE OFFLINE" (R40 below) and its
  `useCanMutate` split (shopping uses `useEmailVerificationBlock`, plan and cards use `useCanMutate`, both
  from `apps/web/src/lib/session.tsx`) stay binding.

- **Remote images become local copies on write.** Recipe create and PATCH, the import commit and the
  collection create/update run `imageUrl` / `coverImageUrl` through `localizeImageUrl`
  (`apps/api/src/modules/recipe/services/recipes/remoteImage.ts`): an `http(s):` or `data:image/` value is
  downloaded with the URL importer's `downloadHeroImage` (SSRF guard, 4 MB / 8 s, magic-byte sniff) BEFORE
  the transaction opens, and the column stores `/uploads/<file>`. Best-effort: a failed download keeps the
  remote URL and the save succeeds; a PATCH that sends back the unchanged remote URL is not retried (no
  8 s wait on every edit of a recipe whose source is gone; `recipe:localize-images` retries those). Under
  `bun test` the default downloader never touches the network; `apps/api/test/recipe-remote-image.test.ts`
  installs one with `setRemoteImageDownloaderForTests`.

- **Inherited recipe gotchas stay binding inside `modules/recipe`** (SPEC D13): read toon-recipe's
  `CLAUDE.md` before touching search (pre-folded columns), import (SSRF guard, JSON-LD `@graph`
  references), OCR subprocesses, cards (EAN check digits, crispEdges), print styles and the shopping
  merge rules. Section 4b maps each of its 83 gotchas to its place here.

- **Printing a recipe (verified by printing to PDF, M4-T09).** `print.css`'s `[hidden]` override must sit in
  `@layer base`: the shell's `[hidden]{display:none!important}` is layered, and an UNLAYERED `!important`
  rule loses to a layered one regardless of specificity (the old override measured `display: none`).
  `useMediaQuery` (`apps/web/src/lib/viewport.ts`) holds the last on-screen value while
  `matchMedia("print")` matches, because the browser
  evaluates media queries against the paper width during a print and a 390px window flipped the detail to
  the desktop markup mid-snapshot (a truncated two-column hybrid, steps 3 to 7 missing). Re-verify with
  `page.emulateMedia({media:"print"})` + `page.pdf()` + `pdftotext` at 390 and 1440 whenever the detail
  screen's markup changes; none of the five gates sees a broken print stylesheet. The stylesheet is
  `apps/web/src/modules/recipe/features/recipes/print.css` (guard:
  `apps/web/src/modules/recipe/features/recipes/print-css.test.ts`). The M4 observation that the printed
  phone detail still carried the servings scaler and "Zur Einkaufsliste" is closed (M7-T01): the phone
  action row carries `data-print="hide"` like the desktop branch, and the test fails on the old markup.

## 5. Verification

Run from the repository root. The recipe-specific checks, on top of the five gates of `CLAUDE.md`
(`bun run typecheck`, `bun test`, `bun run build`, `bun run i18n:check` read by hand):

**The recipe LINKS grep.** `tsc` does not check the links of recipe screens (`AppLink` and
`useAppNavigate` take `to: string`, and `features/import/lib/navigation.ts` builds template strings), so an
unprefixed target such as `/plan` compiles and lands on `NotFoundPage`. The grep is the check; it finds
toon-recipe's 46 old targets in the source tree and nothing in this one. Run it after every web port:

```bash
! grep -rnE "(\bto[=:] ?|\bgo\(|\bgoTo\()[\"'\`]/(recipes|plan|shopping|import|collections|tags|search|groups)\b|\bto[=:] ?[\"']/[\"']|useUrlRecipeFilters\([\"']/[\"']\)" apps/web/src/modules/recipe
```

A headless pass that clicks the links is the second check (`CLAUDE.md` "Headless runs").

**Test files.** API (`apps/api/test/`): `recipe-module.test.ts`, `recipe-cross-household.test.ts`,
`recipes.test.ts`, `recipes-search.test.ts`, `recipes-cooked.test.ts`, `tags-kind.test.ts`, `plan.test.ts`,
`cards.test.ts`, `shopping.test.ts`, `shopping-bought.test.ts`, `shopping-from-plan.test.ts`,
`thumbnails.test.ts`, `uploads.test.ts`, `verified-email-gate.test.ts`, the import suite
`apps/api/test/import/` (`routes`, `commit`, `ocr-disabled`, `ocr-segment`, `ocr-tesseract`,
`pdf-rasterize`, `ssrf`, `url-extract`, `url-pipeline`) with fixtures in `apps/api/test/fixtures/import/`,
and `legacy-recipe.test.ts` for the migration. Shared (`packages/shared/test/`): `barcode`, `qr`, `cards`,
`duration`, `ingredients`, `numbers`, `units`, `shopping`, `tags` and `recipe-schemas` (`.test.ts`). Web
(co-located, under `apps/web/tsconfig.test.json`): `manifest.test.ts`, `persist.test.ts`,

`features/cards/lib/formats.test.ts`, `features/import/lib/{confidence,draftEdit,importErrors}.test.ts`.
Never skip silently: a ported test that needs unported code is removed with a placeholder naming the
milestone that returns it. Never `mock.module`: use the explicit seams (`setMailer`, `setOcrEngine`,
`setPdfRasterizer`, `setOcrImportEnabled`, `setPdfImportEnabled`, `setVerifiedEmailRequired`) and hand
each back in `afterAll`.

**Import and OCR.** `bun test apps/api/test/import` needs poppler's `pdftoppm` for `pdf-rasterize.test.ts`
(CI installs it; the test fails, never skips, without it). No test runs real OCR; verify the `tesseract`
binary by building the image with `--build-arg WITH_OCR=1` and importing a photo. Verify DDL through
`@libsql/client`, never `bun:sqlite`.

**Print to PDF.** None of the five gates sees a broken print stylesheet. Whenever the recipe detail's markup
or `print.css` changes, print from a real browser at 390 and 1440 px:
`page.emulateMedia({media:"print"})`, `page.pdf()`, then `pdftotext`, and check that both the ingredients
and the method are in the PDF, the app chrome and the open menu are not, and the phone detail's scaler and
"Zur Einkaufsliste" are hidden (M7-T01). The M4 run printed the detail at both widths (plan
`docs/plans/m4-design-pass.md` section 9.8).

**Camera scanner.** The wasm decoder and the camera cannot be covered by a unit test; the round trip test
covers the encoders against zxing. To exercise the scan path headless, start Chromium with
`--use-fake-device-for-media-stream` and `--use-file-for-fake-video-capture=<file>.y4m`, grant
`permissions: ["camera"]`, render a barcode with the repo's own encoder (`packages/shared/src/modules/recipe/barcode.ts`),
convert the PNG with `ffmpeg -loop 1 -i x.png -t 3 -r 15 -pix_fmt yuv420p -s 640x480 -f yuv4mpegpipe`,
then open the card form and press the scan button: it checks the `?url` wasm asset resolving, the decode
loop and that the form receives the right format as well as the right value. The M2 headless run did not
exercise the camera; toon-recipe's run did (gotcha R56).

**Phone layout.** Verify in a real headless browser (mobile context at 390x844, `scrollWidth <=
clientWidth`, the gap between a bottom bar and the tab bar), never by reading Tailwind classes; the
procedure and its traps are in `CLAUDE.md` "Headless runs". Offline behaviour is checked on the built app
(`bun run build`, then `WEB_DIST_DIR=./apps/web/dist bun run start`); the dev server has no service
worker.
